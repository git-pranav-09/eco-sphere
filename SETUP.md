# Echo Sphere — setup guide

This repository uses **Render for the public full-stack website** and **Supabase PostgreSQL for the database**. The React/Vite frontend and Express API run together on Render.

## Before starting

Ask a parent or guardian to help with account setup and any account or billing prompts. Keep passwords and API secrets private.

## 1. Create the Supabase database

1. Create a Supabase project on the Free plan.
2. Open **SQL Editor** and run the full contents of `db/schema.sql`.
3. Open **Project Settings → Database → Connect** and select the **Session pooler** connection string.
4. Copy the connection string and keep it private. Do not paste it into GitHub or frontend code.

The Express server creates its session table automatically when it starts.

## 2. Create Google sign-in credentials

1. In Google Cloud Console, create/select a project and configure the OAuth consent screen.
2. Create an OAuth client ID with application type **Web application**.
3. Add the Render site URL as an authorized JavaScript origin after Render gives you the public URL.
4. Add this authorized redirect URI:
   `https://YOUR-RENDER-SERVICE.onrender.com/auth/google/callback`
5. Keep the client secret private.

## 3. Deploy on Render

1. Open Render and choose **New → Blueprint**.
2. Connect `git-pranav-09/eco-sphere` and select its `main` branch.
3. Render reads `render.yaml` and creates the web service.
4. In the service's **Environment** settings, add:
   - `DATABASE_URL` — Supabase Session pooler connection string
   - `APP_BASE_URL` — exact public Render URL
   - `GOOGLE_CLIENT_ID` — Google OAuth client ID
   - `GOOGLE_CLIENT_SECRET` — Google OAuth client secret
   - `INITIAL_SUPER_ADMIN_EMAIL` — the one Google account that should administer Echo Sphere
5. Keep `NODE_ENV=production` and the `SESSION_SECRET` generated by the Blueprint. If adding the session secret manually, use a random value at least 32 characters long.
6. Save the variables and deploy/redeploy.

## 4. Sign in to the admin panel

1. Visit `https://YOUR-RENDER-SERVICE.onrender.com/admin/login`.
2. Choose **Continue with Google**.
3. Use the exact email entered in `INITIAL_SUPER_ADMIN_EMAIL`.
4. The admin dashboard is at `https://YOUR-RENDER-SERVICE.onrender.com/admin/`.

Only verified Google accounts with a matching `admin_roles` record can enter the dashboard. The server inserts the initial super-admin record during startup.

## 5. Test before sharing

- Open the public homepage in a private browser window.
- Submit a test story and confirm it appears as pending in the admin dashboard.
- Approve it and confirm it appears publicly.
- Reject another test story and confirm it does not appear publicly.
- Test sign-out and confirm that the dashboard redirects to login.
- Try a different Google account and confirm it is denied admin access.
- Test on a phone as well as a desktop.

## Free-tier expectations

Render Free services sleep after inactivity, so the first request may be slow while the service wakes. Supabase Free databases may pause after inactivity and have storage/usage quotas. Check current provider limits before launch. This setup is intended for a school project and small demonstration, not guaranteed always-on production hosting.

## Important

- Never share or commit database URLs, Google client secrets or session secrets.
- Do not publish personal or sensitive information in stories.
- Keep story locations broad (country level only).
- Human moderation is required; AI does not make publication decisions.
- The new Supabase database does not automatically contain stories from the old Hatchable database.
